*NLP Foundations · Post 4/4*

## What this post is

Handwritten notes on classical information retrieval. Inverted indices, term-weighting (TF-IDF, BM25), and the ranking functions that power any search engine. Once you've seen these, RAG over a vector database becomes obvious — it's the same problem, with embeddings instead of word counts.

## Key takeaways (so you can scan)

- **Inverted index:** the data structure behind every search engine. Maps each term to the documents that contain it.
- **BM25** is the workhorse ranking function — still competitive against neural retrieval on many benchmarks.
- Modern RAG = the same IR pipeline, but the score comes from cosine similarity over embeddings instead of term frequencies.
