*Machine Learning from Scratch · Part 10/12*

[Part 9](/blog/ml-from-scratch-09-svm) used kernels to *add* dimensions. This post does the opposite — **remove dimensions** to make data more useful.

<Callout color="blue">
  <strong>The one sentence:</strong> <Highlight>PCA doesn't change the data — it changes the perspective from which the data is described.</Highlight>
</Callout>

## Feature selection vs. dimensionality reduction

Two ways to shrink a dataset:

- <KeyTerm>Feature selection</KeyTerm> — drop irrelevant features. You keep your originals.
- <KeyTerm>Dimensionality reduction</KeyTerm> — *transform* first, then drop dimensions in the new space.

| | Feature selection | PCA |
| --- | --- | --- |
| What it returns | Subset of original features | New axes (blends of features) |
| Interpretability | Preserved | Reduced |
| Mechanism | Drops columns | Rotates, then drops dimensions |
| Methods | Chi-Square, Lasso | PCA, Kernel PCA, LDA |

<Arrow>In PCA we don't remove individual features. We create new dimensions formed as linear combinations of the originals.</Arrow>

## Why high dimensions hurt

Imagine looking for a friend in a one-storey house, then a ten-storey building, then a skyscraper. Each new floor *multiplies* the rooms. That's what adding a feature does — the search space inflates, the data gets sparse, distance-based methods stop meaning much.

## PCA: the map of Italy

Italy on the usual North–South / East–West grid. The points spread diagonally — the axes are *valid*, but they don't describe the structure.

Rotate the map slightly. **The points don't move. Distances don't change. The perspective does.** Suddenly each region clusters along one axis.

<Image

  alt="Italy on N–S/E–W axes vs the same map rotated so the new axes are PC1 and PC2, with clusters aligned."
  caption="Same data, same distances — new perspective."
/>

| Italy example | PCA meaning |
| --- | --- |
| Original map orientation | Original feature space |
| N–S and E–W axes | Original variables |
| Rotating the map | Changing the coordinate system |
| Better-separated regions | Structure becomes clearer |
| New axes after rotation | Principal components |

<Callout color="yellow">
  💡 PCA finds this rotation automatically. <Highlight>It compresses by combining correlated features.</Highlight> No correlations → nothing to compress.
</Callout>

## Principal components are recipes

Each PC is a fixed blend of the original ingredients — a bit of `income`, a dash of `age`, a pinch of `zipcode`.

`PC₁ = w₁·x₁ + w₂·x₂ + … + wₚ·xₚ`

PCA orders them:

- **PC₁** — most variability of any possible blend.
- **PC₂** — most *remaining* variability, uncorrelated with PC₁.
- **PC₃** — same idea, uncorrelated with PC₁ and PC₂.

You get the same number of PCs as you had features. **The reduction is your call afterwards** — keep the top K.

<Callout color="green">
  <strong>Do say:</strong> "PCA creates new dimensions from combinations of the original variables."<br/>
  <strong>Don't say:</strong> "PCA selects the best original features." That's feature selection, not PCA.
</Callout>

<Callout color="pink">
  <strong>The explainability tax.</strong> Every PC blends your features. Your model now runs on <code>0.3·income + 0.6·age + 0.2·zipcode + …</code>. <Highlight>Don't use PCA when explainability is the deliverable</Highlight> — reach for Lasso or RF feature importance.
</Callout>

## When PCA is pointless

PCA bundles correlated features. So:

<Image
  src="/images/blog/ml-from-scratch/pca/pca-correlated-data.png"
  alt="Two strongly correlated variables X and Y on a scatter, Y = X plus small noise."
  caption="Two variables, one direction of information. PCA's whole job."
/>

<Callout color="orange">
  ⚠️ No correlations → no compression. You'll end up with as many components as features, each carrying the same variance.
</Callout>

PCA is a <KeyTerm>technique</KeyTerm>, not an algorithm. It transforms; it doesn't predict.

## PCA vs LDA

PCA ignores the target — it's unsupervised. If you have labels and want axes that maximise *class separation*, that's <KeyTerm>LDA</KeyTerm> ([Part 11](/blog/ml-from-scratch-11-lda-qda)).

| | PCA | LDA |
| --- | --- | --- |
| Target labels? | No | Yes |
| Maximises | Total variance | Class separation |
| Used for | EDA, compression, viz | Classification prep |

## Two things that quietly break PCA

**Scaling.** A feature in the thousands (`income`) will dominate a feature in single digits (`age`) by magnitude alone — like a loud speaker drowning out a quiet one. **Always scale first.**

<Image
  src="/images/blog/ml-from-scratch/pca/pca-scaling-comparison.png"
  alt="PCA on the same data, unscaled vs scaled. Unscaled: classes overlap. Scaled: classes separate cleanly."
  caption="Same dataset. Left: raw features. Right: standardised. The classes only show up after scaling."
/>

**Skewness.** Variance is a poor summary for skewed data. Log or Box-Cox transform first.

<Image
  src="/images/blog/ml-from-scratch/pca/skewness-distributions.png"
  alt="Right-skewed, symmetric, and left-skewed distributions showing mean and median positions."
  caption="Median is stable under skew; mean drifts. PCA uses variance around the mean — so skewed features fight it."
/>

## The maths sketch

PCA is built on the **covariance matrix** Σ — a `p × p` matrix of feature-pair covariances, with variances on the diagonal.

<Image
  src="/images/blog/ml-from-scratch/pca/pca-covariance-matrix.png"
  alt="A covariance matrix Σ with entries cov(x,x), cov(x,y), cov(y,x), cov(y,y)."
  caption="Symmetric — cov(x,y) = cov(y,x). That symmetry is what makes the next step possible."
/>

<Callout color="yellow">
  <strong>Stats refresher.</strong> PCA only really uses two ideas: <strong>variance</strong> (how spread out a feature is, around its mean) and <strong>covariance</strong> (how two features move together). Correlation is just covariance scaled to [−1, 1].
</Callout>

<Image
  src="/images/blog/ml-from-scratch/pca/covariance-correlation.png"
  alt="Definitions of covariance and correlation."
  caption="Covariance: direction of the relationship. Correlation: direction and strength, on a comparable scale."
/>

The **spectral decomposition theorem**: any symmetric matrix factors as `Σ = U · Λ · U⁻¹`, where U's columns are the <KeyTerm>eigenvectors</KeyTerm> and Λ's diagonal holds the <KeyTerm>eigenvalues</KeyTerm>.

<Image
  src="/images/blog/ml-from-scratch/pca/pca-eigendecomposition.png"
  alt="Spectral decomposition: diagonal Λ of eigenvalues equals U inverse times Σ times U."
  caption="Columns of U are eigenvectors (directions). Λ's diagonal holds the eigenvalues (variance along each direction)."
/>

**The eigenvectors are the principal components. The eigenvalues are the variance each one captures.**

<Callout color="blue">
  <strong>The mnemonic:</strong> <Highlight>Eigenvector = where to look. Eigenvalue = how much there is to see.</Highlight>
</Callout>

## How many components?

PCA can't decide for you. Four criteria:

**1. Elbow on the scree plot.** Drop fast, then flatten — keep what's to the left of the bend.

<Image
  src="/images/blog/ml-from-scratch/pca/pca-scree-elbow.png"
  alt="Scree plot — variance per principal component, descending, with the elbow at PC4."
  caption="The 'elbow' marks where extra PCs stop buying you much variance."
/>

**2. Cumulative variance.** Pick a target (often 90–95%) and read off how many PCs you need.

<Image
  src="/images/blog/ml-from-scratch/pca/pca-cumulative-variance.png"
  alt="Cumulative explained variance curve rising and asymptoting toward 1."
  caption="Cumulative variance explained — pick a threshold, count PCs."
/>

**3. Eigenvalue > 1 (Kaiser).** Keep PCs whose eigenvalue exceeds 1 (they carry more variance than the average original feature did).

**4. Cross-validation.** Treat K as a hyperparameter, train downstream, pick the K with best CV score.

```python
from sklearn.decomposition import PCA
pca = PCA(n_components=0.95)   # keep enough PCs to hit 95% variance
X_reduced = pca.fit_transform(X_scaled)
```

## Kernel PCA

Same kernel trick as [Part 9](/blog/ml-from-scratch-09-svm). By default PCA finds *linear* combinations; a kernel makes them *non-linear*. Rarely worth it in practice — autoencoders are usually a better tool for wild non-linear structure.

## End-to-end on the Wine dataset

13 chemical features, 3 cultivar classes, no labels used by PCA:

```python
from sklearn.datasets import load_wine
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
import matplotlib.pyplot as plt

X, y = load_wine(return_X_y=True)
X_scaled = StandardScaler().fit_transform(X)        # 1. scale
pcs = PCA(n_components=2).fit_transform(X_scaled)   # 2. project to 2D

plt.scatter(pcs[:, 0], pcs[:, 1], c=y, cmap="viridis")
plt.xlabel("PC1"); plt.ylabel("PC2"); plt.show()
```

Variance explained: **PC1 ≈ 36%**, **PC1+PC2 ≈ 55%**, **first 7 PCs ≈ 90%**. The three cultivars separate cleanly in PC1–PC2 space — even though PCA never saw the class labels.

This *isn't* always the case. When class structure is orthogonal to maximum-variance directions, LDA wins. That's [Part 11](/blog/ml-from-scratch-11-lda-qda).

## The workflow

1. Drop the target. PCA is unsupervised.
2. **Scale on training only.** Fit `StandardScaler` on train, transform train + test.
3. Fit PCA on the scaled training set.
4. Pick K — scree, cumulative, or CV.
5. Transform train + test, fit your downstream model.

<Callout color="orange">
  ⚠️ Fit the scaler and PCA on train, then <em>transform</em> validation/test with the fitted objects. Re-fitting on test = leakage.
</Callout>

## Takeaways

- PCA **combines correlated features** into uncorrelated PCs.
- PC₁ holds the most variance, each later PC the most remaining.
- Needs **correlated, scaled, roughly-normal** data.
- Costs **explainability** — features become blends.
- It's **unsupervised**. Supervised cousin is LDA.
- It's **preprocessing**, not prediction.

<Callout color="green">
  <strong>Where I use PCA:</strong> before clustering or viz on high-D data; as preprocessing when many features are correlated; for EDA — PC1 vs PC2 often shows structure you can't see raw.<br/><br/>
  <Highlight>Where I don't: when explainability matters, or when features aren't correlated.</Highlight>
</Callout>
